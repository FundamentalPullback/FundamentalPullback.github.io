# Daily website publication checklist

These checks maintain the existing Fundamental Pullback website. They do not change the investment plan, holdings, orders or research approvals.

1. **Publish supplied data, not an assumed feed.** Daily scanner exports and research must first be supplied, checked and published. The website does not independently ingest new daily scanners or complete research. Keep the original export and its timestamp, timezone ambiguity and raw fields. Store verified corrections separately.
2. **Append and preserve.** Add the new scanner chunk to `manifest.files`; keep prior chunks, dates, reports and source files. Add new library chunks to `manifest.libraryFiles`. Keep stable report IDs and ticker links. Do not overwrite historical scanner observations with later prices.
3. **State research depth honestly.** Use explicit per-ticker report metadata for standalone reports. Label preliminary, partial, blocked or conditional work accordingly. Publication date, last mention, last review and last completed analysis are separate facts. Missing dates stay unavailable. Publication never grants a new approval or trade permission.
4. **Keep the searchable card current.** Each ticker is derived from published scanner, decisions, management, operations and research data. Verify a newly introduced ticker and an existing ticker with new analysis. The first card shows the appropriate dated scanner price, model/scenarios, concise qualified comment and report links. Do not turn research sensitivities into certified values.
5. **Keep closes separate.** The main summary card has no documented-close tile. Retain historical regular-session closes and explicitly documented report close facts in their source records and history. Never relabel scanner Last, delayed live prices, sale executions or snapshot quotes as a regular close. Show actual source/session dates; withhold missing or conflicting values. Preserve conditional, stale and uncertified caveats.
6. **Refresh quote listing identities.** After adding scanner/research data, run `python3 tools/prepare-publication.py`. It derives the complete profile universe, downloads fresh official exchange directories, updates display-only TradingView identity maps, runs all profile/card/quote checks, and advances the publication version. Include both generated `data/tradingview-*.js` files and the manifest in the same release. It requires Python 3, Node.js and public network access, but no account, API key or new permissions. It does not publish or ingest scanner data by itself. New known listings resolve automatically; ambiguous, delisted, unknown-venue and unsupported symbols stay visibly unavailable rather than guessing another security. Treat refresh failure as a blocked quote-map update, not a successful fresh publication. See `tools/quote-provider.md`.
7. **Keep Hoy latest-only.** `latestScannerNotice()` derives its date and counts from the latest valid scanner date. Do not append hardcoded daily scanner banners to Hoy. Previous notices and scans belong in the date-selectable Daily overview / Scanner archive. Test a synthetic next-day scan to confirm rollover without code changes.
8. **Refresh publication version.** Advance `manifest.generated` for every release, retaining unrelated manifest fields. The open, visible site checks for a new version every minute and reloads its current ticker link when one appears. New data becomes searchable after deployment; there is no separate index rebuild.
9. **Run checks and verify live.** Run `node tools/test-stock-profiles.cjs` `node tools/test-stock-cards.cjs` and `node tools/test-stock-quotes.cjs`; check ES/EN, a narrow layout, latest-only Hoy, a new ticker, a revised analysis, missing values and source links. Confirm the expected commit/deployment and public pages. Report failed freshness or source availability instead of describing a stale or failed update as current.
10. **Account performance is a separate publication.** Calendar history and realized account figures follow their authorized publication workflow. Do not fold new account data into a scanner/search-only release. Use the separate validated performance publisher and its instructions when authorized; do not infer daily automation from the search refresh behavior.

See `tools/stock-profiles.md` for source metadata and card selection details. Older research remains accessible through stock profiles and the Library.
